# [디지털 포렌식] 실습 01 — Windows 기반 파일 무결성 검증 (SHA-256)

> 원본 자료: `원본자료/01_파일무결성검증실습.pdf`, `원본자료/Windows_SHA256_File_Integrity_Check.c`
> 라인별 주석 코드: `file_integrity.c`

---

## 0. 자료 분석 요약

| 구분 | 내용 |
|---|---|
| 실습 환경 | Windows 10/11 + VS Code + `cl.exe`(MSVC 컴파일러) |
| 사용 기술 | Windows CNG(BCrypt) API를 이용한 SHA-256 해시 계산 |
| 실습 목표 | 원본 파일과 복사된 증거 파일의 SHA-256 값을 계산·비교하여 무결성 판단 |
| 판단 기준 | 해시값 A == B → **무결성 유지** / A != B → **파일 변경 가능성** |
| 핵심 교훈 | 파일 **이름이나 크기**가 같다고 같은 증거가 아니다. 파일의 **실제 데이터**로 만든 SHA-256 값을 비교해 무결성을 검증한다. |

```
원본 파일 (original.txt)  ──SHA-256──▶  해시값 A ─┐
                                                   ├─ 비교 ─▶ A == B : 무결성 유지
증거 파일 (evidence.txt)  ──SHA-256──▶  해시값 B ─┘          A != B : 변경 가능성
```

### 프로그램 동작 흐름 (`calculateSHA256` 함수 7단계)

| 단계 | 사용 API | 역할 |
|---|---|---|
| 1 | `CreateFileA(GENERIC_READ)` | 증거 파일을 **읽기 전용**으로 열기 (원본 훼손 방지) |
| 2 | `BCryptOpenAlgorithmProvider` | SHA-256 알고리즘 공급자 열기 |
| 3 | `BCryptGetProperty(BCRYPT_OBJECT_LENGTH)` | 해시 객체에 필요한 메모리 크기 조회 |
| 4 | `HeapAlloc` | 해시 객체용 메모리 할당 |
| 5 | `BCryptCreateHash` | 해시 객체 생성 |
| 6 | `ReadFile` + `BCryptHashData` (반복) | 파일을 4096바이트씩 읽어 해시에 누적 (대용량 파일도 처리 가능) |
| 7 | `BCryptFinishHash` | 최종 32바이트(256비트) 해시값 확정 → 자원 반환 |

이후 `main`에서 두 파일의 해시를 `printHash`로 64자리 16진수로 출력하고, `compareHash`로 32바이트를 하나씩 비교해 결과를 판정합니다.

## 1단계. 실습 환경 준비

1. **Visual Studio Build Tools(또는 Visual Studio Community) 설치**
   - 설치 관리자에서 **"C++를 사용한 데스크톱 개발"** 워크로드를 선택합니다.
   - 이 워크로드에 `cl.exe`, Windows SDK(`bcrypt.h`, `bcrypt.lib` 포함)가 들어 있습니다.
2. **VS Code 설치** 후 확장 프로그램 **C/C++ (Microsoft)** 를 설치합니다.
3. **개발자 명령 프롬프트 실행**
   - 시작 메뉴 → **"Developer Command Prompt for VS"** (또는 "x64 Native Tools Command Prompt")를 엽니다.
   - 일반 `cmd`나 PowerShell에서는 `cl`을 찾지 못합니다. VS Code를 쓸 때도 이 프롬프트에서 `code .`로 실행해야 VS Code 터미널에서 `cl`을 쓸 수 있습니다.
4. 컴파일러 확인:
   ```bat
   cl
   ```
   `Microsoft (R) C/C++ Optimizing Compiler ...` 메시지가 보이면 준비가 끝난 것입니다.

## 2단계. 작업 폴더와 소스 코드 준비

```bat
mkdir C:\Forensic
cd C:\Forensic
```

- `file_integrity.c`를 `C:\Forensic` 폴더에 복사합니다. 주석 버전과 원본 버전 중 어느 것을 써도 결과는 같습니다.
- 파일은 **UTF-8 인코딩**이어야 합니다. VS Code 오른쪽 아래 상태 표시줄에서 `UTF-8`인지 확인하세요.

## 3단계. 컴파일

Windows BCrypt API를 쓰므로 `bcrypt.lib`를 링크해야 합니다.

```bat
cl /W4 /utf-8 file_integrity.c bcrypt.lib
```

코드에 `#pragma comment(lib, "bcrypt.lib")`가 이미 있으므로 아래처럼 써도 됩니다.

```bat
cl /W4 /utf-8 file_integrity.c
```

| 옵션 | 의미 |
|---|---|
| `/W4` | 경고 수준 4: 잠재적 오류를 최대한 많이 보여 줌 |
| `/utf-8` | 소스 코드와 실행 문자열을 UTF-8로 처리 (한글 출력이 깨지지 않게 함) |

컴파일에 성공하면 `file_integrity.obj`와 **`file_integrity.exe`** 가 생성됩니다.

## 4단계. 테스트 파일(원본 증거) 만들기

메모장으로 `C:\Forensic\original.txt`를 만들고 아래 내용을 입력한 뒤 저장합니다.

```
Digital Forensic Evidence
Windows 11
2026
```

## 5단계. 증거 사본 만들기

같은 파일을 복사해 `evidence.txt`를 만듭니다. 탐색기에서 복사해도 되고 명령어를 써도 됩니다.

```bat
copy C:\Forensic\original.txt C:\Forensic\evidence.txt
```

> 메모장에서 "다른 이름으로 저장"을 하거나 내용을 다시 타이핑하지 마세요. 줄바꿈 방식이나 인코딩이 달라져 해시가 바뀔 수 있습니다. 반드시 **파일 복사**로 만듭니다.

## 6단계. 실험 ① — 무결성 유지 확인 (해시 일치)

```bat
file_integrity.exe
```

```
=========================================
 Digital Forensic File Integrity Check
 SHA-256 File Hash Verification
=========================================

원본 파일 경로 입력 : C:\Forensic\original.txt
비교 파일 경로 입력 : C:\Forensic\evidence.txt

-----------------------------------------
[원본 파일]
파일 : C:\Forensic\original.txt
SHA-256 : 8a46f82c...

[비교 파일]
파일 : C:\Forensic\evidence.txt
SHA-256 : 8a46f82c...
-----------------------------------------
[검증 결과]
SHA-256 값이 같습니다.
파일의 무결성이 유지되었습니다.
-----------------------------------------
```

- 두 SHA-256 값(64자리)이 **완전히 같으면** 무결성이 유지된 것입니다.
- PDF의 `8a46f82c...`는 예시입니다. 실제 값은 줄바꿈(CRLF), 마지막 줄 끝의 엔터 여부 등에 따라 달라지므로 학생마다 다를 수 있습니다. 중요한 것은 **두 값이 서로 같은지**입니다.

## 7단계. 실험 ② — 변조 탐지 (해시 불일치)

1. 메모장으로 `evidence.txt`를 열어 **글자 하나만** 추가하고 저장합니다. 예: `2026` → `2026.`
2. 프로그램을 다시 실행해 같은 경로를 입력합니다.

```
[원본 파일]
SHA-256 : 8a46f82c...

[비교 파일]
SHA-256 : 5b921ad7...
-----------------------------------------
[검증 결과]
SHA-256 값이 다릅니다.
파일 내용이 변경되었을 가능성이 있습니다.
-----------------------------------------
```

- 단 1바이트가 바뀌었는데도 해시값 전체가 완전히 달라집니다. 이것을 **눈사태 효과(Avalanche Effect)** 라고 합니다.

## 8단계. 결과 정리 및 핵심 개념 확인

실험 결과를 표로 기록합니다.

| 실험 | 원본 SHA-256 (앞 8자리) | 증거 SHA-256 (앞 8자리) | 판정 |
|---|---|---|---|
| ① 단순 복사 | | | 무결성 유지 / 변경 가능성 |
| ② 1글자 추가 | | | 무결성 유지 / 변경 가능성 |

**핵심 정리:** 파일 이름이나 크기가 같다고 같은 증거라고 판단하면 안 됩니다. 파일의 **실제 데이터**로 만든 SHA-256 해시값을 비교해야 무결성을 검증할 수 있습니다.

## (심화) 추가 실험 — PDF의 핵심 메시지를 직접 증명하기

PDF에 실린 실습은 7단계까지입니다. 아래 실험은 PDF의 결론("이름·크기가 아닌 데이터로 판단한다")을 직접 확인해 보도록 덧붙인 것입니다.

### 실험 ③ — 크기는 같은데 내용이 다른 경우
`evidence.txt`를 다시 `original.txt`로 복사해 되돌린 뒤 `2026`을 `2025`로 바꿉니다. 글자 수는 그대로입니다.

```bat
copy /Y C:\Forensic\original.txt C:\Forensic\evidence.txt
dir C:\Forensic\*.txt
```
→ 수정 후에도 `dir`로 보는 **파일 크기는 같지만**, 해시값은 **다릅니다**. 크기만으로는 동일성을 판단할 수 없습니다.

### 실험 ④ — 이름은 다른데 내용이 같은 경우
```bat
copy C:\Forensic\original.txt C:\Forensic\renamed_copy.txt
```
→ 파일 이름이 달라도 해시값은 **같습니다**. 이름, 생성·수정 시각 같은 메타데이터는 파일 시스템(NTFS)에 따로 저장되므로 내용 해시에 영향을 주지 않습니다.

### 실험 ⑤ — Windows 기본 도구로 교차 검증
포렌식에서는 결과를 **서로 다른 도구로 교차 검증**하는 것이 원칙입니다. 프로그램이 출력한 값과 아래 명령의 결과가 같은지 확인합니다.

```bat
:: 명령 프롬프트
certutil -hashfile C:\Forensic\original.txt SHA256
```
```powershell
# PowerShell
Get-FileHash C:\Forensic\original.txt -Algorithm SHA256
```
`Get-FileHash`는 대문자 16진수로 출력합니다. 16진수는 대소문자를 구분하지 않으므로 같은 값입니다.

## 문제 해결 (Troubleshooting)

| 증상 | 원인 및 해결 |
|---|---|
| `'cl'은(는) 내부 또는 외부 명령...이 아닙니다` | 일반 cmd에서 실행함 → **Developer Command Prompt for VS**에서 실행 |
| PowerShell(VS Code 터미널): `cl : 'cl' 용어가 cmdlet, 함수, 스크립트 파일 또는 실행할 수 있는 프로그램 이름으로 인식되지 않습니다` | 개발자 환경이 로드되지 않은 터미널 → 아래 **"VS Code PowerShell 터미널에서 cl 사용하기"** 참고 |
| `cannot open include file 'bcrypt.h'` | Windows SDK 미설치 → VS 설치 관리자에서 "C++를 사용한 데스크톱 개발" 워크로드 설치 |
| `LNK2019: unresolved external symbol BCrypt...` | `bcrypt.lib` 링크 누락 → 컴파일 명령에 `bcrypt.lib` 추가 |
| 한글 출력이 깨짐 | `/utf-8` 옵션 누락 또는 소스가 UTF-8이 아님 → 옵션과 파일 인코딩 확인 |
| `파일 열기 실패`, `Error Code : 2` | 파일이 없음 → 경로와 확장자 확인 (탐색기에서 "파일 확장명 표시" 켜기, `original.txt.txt` 주의) |
| `Error Code : 3` | 폴더 경로가 없음 → `C:\Forensic` 폴더 존재 여부 확인 |
| `Error Code : 5` | 접근 거부 → 권한 확인 또는 다른 폴더 사용 |
| `Error Code : 32` | 다른 프로그램이 파일을 쓰기 모드로 열고 있음 → 해당 프로그램을 닫고 재실행 |
| 공백이 있는 경로를 입력하면 실패 | `scanf_s("%259s")`는 **공백 전까지만** 읽음 → 경로에 공백이 없는 폴더(예: `C:\Forensic`) 사용 |
| 한글이 들어간 경로가 열리지 않거나 깨져 보임 | 경로는 **영문**으로 구성하는 것을 권장 |

### VS Code PowerShell 터미널에서 cl 사용하기

`cl.exe`는 설치되어 있어도 PATH에 등록되지 않으므로, 일반 PowerShell에서는 개발자 환경을 먼저 불러와야 합니다.

**방법 1. 현재 터미널에 개발자 환경 불러오기 (가장 빠름)** — 터미널을 열 때마다 한 번 실행합니다.

```powershell
$vs = & "${env:ProgramFiles(x86)}\Microsoft Visual Studio\Installer\vswhere.exe" -latest -products * -requires Microsoft.VisualStudio.Component.VC.Tools.x86.x64 -property installationPath
Import-Module "$vs\Common7\Tools\Microsoft.VisualStudio.DevShell.dll"
Enter-VsDevShell -VsInstallPath $vs -SkipAutomaticLocation -DevCmdArguments "-arch=x64 -host_arch=x64"
cl /W4 /utf-8 file_integrity.c
```

- `-SkipAutomaticLocation`: 현재 폴더를 그대로 유지합니다 (빼면 `source\repos`로 이동함).
- `-arch=x64`: 64비트 프로그램으로 컴파일합니다.
- 첫 줄에서 `vswhere.exe`를 찾지 못하거나 `$vs`가 비어 있으면 Visual Studio(또는 Build Tools)나 **"C++를 사용한 데스크톱 개발"** 워크로드가 설치되지 않은 것입니다.

**방법 2. 개발자 프롬프트에서 VS Code 실행하기** — 시작 메뉴에서 **Developer PowerShell for VS**를 열고, 실행 중인 VS Code를 모두 닫은 뒤 실행합니다.

```powershell
cd D:\University_Project\Joongbu-Forensic\Forensic
code .
```

이렇게 연 VS Code의 터미널에서는 바로 `cl`을 쓸 수 있습니다.

**확인:** `where.exe cl` 결과로 `...\VC\Tools\MSVC\...\bin\Hostx64\x64\cl.exe` 경로가 나오면 성공입니다. PowerShell에서는 `where`가 다른 명령(`Where-Object`)이므로 반드시 `where.exe`로 입력합니다.
