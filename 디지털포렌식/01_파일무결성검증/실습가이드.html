Windows 파일 무결성 검증 (SHA-256)

원본 파일과 복사된 증거 파일의 SHA-256 해시값을 C 프로그램으로 계산하고 비교합니다. 파일 이름이나 크기가 아니라 실제 데이터로 동일성을 판단하는 방법을 익힙니다.

SHA-256("Digital Forensic Evidence…") → 64자리 16진수, 1바이트만 바뀌어도 전체가 달라짐
환경
Windows 10/11
도구
VS Code + cl.exe
API
Windows CNG (BCrypt)
알고리즘
SHA-256 · 32 Byte
실습 목표 프로그램 동작 실습 단계 해시 체험 심화 실험 주석 코드 문제 해결
실습 목표

해시값 A와 B를 비교해 무결성을 판정한다

원본 파일(original.txt)과 복사한 증거 파일(evidence.txt)의 SHA-256 값을 각각 계산합니다.

A == B파일 무결성 유지
A != B파일 변경 가능성

파일 이름이나 크기가 같다고 같은 증거라고 판단하면 안 됩니다. 파일의 실제 데이터로 만든 SHA-256 해시값을 비교해야 무결성을 검증할 수 있습니다.

프로그램 동작

calculateSHA256 함수의 7단계

단계사용 API역할
1CreateFileA(GENERIC_READ)증거 파일을 읽기 전용으로 열기 (원본 훼손 방지)
2BCryptOpenAlgorithmProviderSHA-256 알고리즘 공급자 열기
3BCryptGetProperty해시 객체에 필요한 메모리 크기 조회 (BCRYPT_OBJECT_LENGTH)
4HeapAlloc해시 객체용 메모리 할당
5BCryptCreateHash해시 객체 생성
6ReadFile + BCryptHashData파일을 4096바이트씩 읽어 해시에 누적 (대용량 파일도 처리)
7BCryptFinishHash최종 32바이트 해시값 확정 후 자원을 역순으로 반환

main은 두 파일의 해시를 printHash로 64자리 16진수로 출력하고, compareHash로 32바이트를 하나씩 비교해 결과를 판정합니다.

실습 단계

순서대로 따라 하기

  1. 실습 환경 준비

    • Visual Studio Build Tools(또는 Community)를 설치하면서 "C++를 사용한 데스크톱 개발" 워크로드를 선택합니다. cl.exe와 Windows SDK(bcrypt.h, bcrypt.lib)가 함께 설치됩니다.
    • VS Code와 확장 프로그램 C/C++ (Microsoft)를 설치합니다.
    • 시작 메뉴에서 Developer Command Prompt for VS를 엽니다. VS Code를 쓰려면 이 프롬프트에서 code .로 실행합니다.
    > cl

    Microsoft (R) C/C++ Optimizing Compiler가 보이면 준비 완료입니다.

  2. 작업 폴더와 소스 준비

    > mkdir C:\Forensic
> cd C:\Forensic

    아래 주석 코드를 복사해 C:\Forensic\file_integrity.c로 저장합니다. VS Code 상태 표시줄에서 인코딩이 UTF-8인지 확인합니다.

  3. 컴파일

    > cl /W4 /utf-8 file_integrity.c bcrypt.lib

    코드에 #pragma comment(lib, "bcrypt.lib")가 있으므로 cl /W4 /utf-8 file_integrity.c만으로도 됩니다. /W4는 경고를 최대한 보여 주고, /utf-8은 한글 출력이 깨지지 않게 합니다. 성공하면 file_integrity.exe가 생깁니다.

  4. 원본 증거 파일 만들기

    메모장으로 C:\Forensic\original.txt를 만들고 다음 세 줄을 저장합니다.

    Digital Forensic Evidence
Windows 11
2026

  5. 증거 사본 만들기

    > copy C:\Forensic\original.txt C:\Forensic\evidence.txt

    주의 내용을 다시 타이핑하거나 "다른 이름으로 저장"하지 마세요. 줄바꿈이나 인코딩이 달라져 해시가 바뀔 수 있습니다. 반드시 파일 복사로 만듭니다.

  6. 실험 ① 무결성 유지 확인

    > file_integrity.exe
    원본 파일 경로 입력 : C:\Forensic\original.txt
비교 파일 경로 입력 : C:\Forensic\evidence.txt

[원본 파일]
SHA-256 : 8a46f82c...
[비교 파일]
SHA-256 : 8a46f82c...
-----------------------------------------
[검증 결과]
SHA-256 값이 같습니다.
파일의 무결성이 유지되었습니다.

    8a46f82c...는 교재의 예시값입니다. 실제 값은 줄바꿈 방식과 마지막 줄 엔터 여부에 따라 학생마다 다를 수 있습니다. 중요한 것은 두 값이 서로 같은지입니다.

  7. 실험 ② 변조 탐지

    evidence.txt에 글자 하나만 추가합니다(예: 2026 → 2026.). 그다음 다시 실행합니다.

    [원본 파일]
SHA-256 : 8a46f82c...
[비교 파일]
SHA-256 : 5b921ad7...
-----------------------------------------
[검증 결과]
SHA-256 값이 다릅니다.
파일 내용이 변경되었을 가능성이 있습니다.

    1바이트만 바뀌어도 해시 전체가 완전히 달라집니다. 이를 눈사태 효과(Avalanche Effect)라고 합니다.

  8. 결과 정리

    실험원본 SHA-256 (앞 8자리)증거 SHA-256 (앞 8자리)판정
    ① 단순 복사무결성 유지 / 변경 가능성
    ② 1글자 추가무결성 유지 / 변경 가능성
해시 체험

브라우저에서 바로 비교해 보기

두 칸의 내용을 바꾸면 SHA-256 값이 즉시 다시 계산됩니다. 서로 다른 16진수 자리는 빨갛게 표시됩니다. 내 컴퓨터의 파일을 골라도 되며, 파일은 브라우저 안에서만 계산되고 어디에도 전송되지 않습니다.

텍스트는 UTF-8로 계산합니다. 메모장 파일과 결과를 맞추려면 CRLF를 켜 두고, 파일 끝에 빈 줄이 있는지도 맞추세요.

심화 실험

교재의 결론을 직접 증명하기

교재의 실습은 실험 ②까지입니다. 아래 실험으로 "이름·크기가 아니라 데이터로 판단한다"는 결론을 직접 확인합니다.

실험 ③ 크기는 같은데 내용이 다른 경우 
> copy /Y C:\Forensic\original.txt C:\Forensic\evidence.txt
> dir C:\Forensic\*.txt

evidence.txt의 2026을 2025로 바꾸면 dir로 본 크기는 그대로지만 해시값은 다릅니다. 크기만으로는 동일성을 판단할 수 없습니다.

실험 ④ 이름은 다른데 내용이 같은 경우 
> copy C:\Forensic\original.txt C:\Forensic\renamed_copy.txt

이름이 달라도 해시값은 같습니다. 파일 이름과 생성·수정 시각은 파일 시스템(NTFS)에 따로 저장되므로 내용 해시에 영향을 주지 않습니다.

실험 ⑤ Windows 기본 도구로 교차 검증

포렌식에서는 결과를 서로 다른 도구로 교차 검증합니다. 프로그램 출력과 아래 결과가 같은지 확인합니다.

cmd> certutil -hashfile C:\Forensic\original.txt SHA256
PS>  Get-FileHash C:\Forensic\original.txt -Algorithm SHA256

Get-FileHash는 대문자로 출력하지만 16진수는 대소문자를 구분하지 않으므로 같은 값입니다.

주석 코드

file_integrity.c

교재 코드와 실행 로직이 완전히 같고, 모든 줄에 한국어 주석을 붙였습니다.

/* * ===================================================================== *  file_integrity.c  —  [디지털 포렌식] Windows 기반 파일 무결성 검증 * ===================================================================== *  원본 파일과 증거(복사) 파일의 SHA-256 해시값을 각각 계산하여 비교한다. *    - 두 해시값이 같으면  → 파일 무결성 유지 *    - 두 해시값이 다르면  → 파일 내용이 변경되었을 가능성 * *  사용 API : Windows CNG(Cryptography API: Next Generation)의 BCrypt 함수 *  컴파일   : cl /W4 /utf-8 file_integrity.c            (Developer Command Prompt) *  주의     : 이 파일은 UTF-8로 저장되어 있으므로 /utf-8 옵션을 반드시 붙인다. * *  ※ 원본 코드(원본자료/Windows_SHA256_File_Integrity_Check.c)와 실행 로직은 *    완전히 동일하며, 학습용으로 라인별 주석만 추가하였다. * ===================================================================== */ #define WIN32_LEAN_AND_MEAN        // windows.h에서 잘 쓰지 않는 헤더(소켓, OLE 등)를 제외해 컴파일 속도를 높인다 #include <windows.h>               // CreateFileA, ReadFile, CloseHandle, HeapAlloc 등 Windows 기본 API 선언#include <bcrypt.h>                // BCryptOpenAlgorithmProvider 등 CNG 암호화(해시) API 선언#include <stdio.h>                 // printf, scanf_s 등 표준 입출력 함수 선언 #pragma comment(lib, "bcrypt.lib") // 링커에게 bcrypt.lib를 자동으로 링크하라고 지시 (명령줄에 lib 생략 가능) #define BUFFER_SIZE 4096           // 파일을 한 번에 읽어 들일 크기: 4096바이트(4KB, 일반적인 디스크 페이지 크기) /* * 파일의 SHA-256 해시값을 계산하는 함수 * * fileName  : 검사할 파일 이름 * hashValue : 계산된 SHA-256 값을 저장할 배열 * * 성공하면 1, 실패하면 0 반환 */int calculateSHA256(const char *fileName, unsigned char hashValue[32]) // SHA-256 결과는 256비트 = 32바이트{                                                   // 함수 본문 시작    HANDLE hFile = INVALID_HANDLE_VALUE;            // 열린 파일을 가리킬 핸들 (초기값: '유효하지 않음')    BCRYPT_ALG_HANDLE hAlgorithm = NULL;            // SHA-256 알고리즘 공급자 핸들    BCRYPT_HASH_HANDLE hHash = NULL;                // 실제 해시 계산을 수행할 해시 객체 핸들    NTSTATUS status;                                // BCrypt 함수의 반환 상태값 (0 = STATUS_SUCCESS = 성공)    DWORD hashObjectSize = 0;                       // 해시 객체가 내부적으로 필요로 하는 메모리 크기(바이트)    DWORD dataSize = 0;                             // BCryptGetProperty가 실제로 기록한 바이트 수    unsigned char *hashObject = NULL;               // 해시 객체용으로 동적 할당할 메모리의 시작 주소    BYTE buffer[BUFFER_SIZE];                       // 파일에서 읽은 데이터를 잠시 담아 둘 4KB 버퍼    DWORD readBytes;                                // ReadFile이 실제로 읽은 바이트 수     /*     * -------------------------------------------------     * 1. 검사할 파일 열기     * -------------------------------------------------     * GENERIC_READ를 사용하므로 파일을 읽기 전용으로 접근한다.     */    hFile = CreateFileA(fileName,                   // 열 파일 경로 (A = ANSI 문자열 버전)                        GENERIC_READ,               // 읽기 권한만 요청 → 증거 파일을 실수로 수정하지 않음(포렌식 원칙)                        FILE_SHARE_READ,            // 다른 프로세스의 '읽기'는 허용, 쓰기/삭제는 차단                        NULL,                       // 보안 속성: 기본값 사용                        OPEN_EXISTING,              // 파일이 이미 존재할 때만 열기 (없으면 새로 만들지 않고 실패)                        FILE_ATTRIBUTE_NORMAL,      // 특별한 속성 없이 일반 파일로 처리                        NULL);                      // 템플릿 파일: 사용하지 않음     if (hFile == INVALID_HANDLE_VALUE)              // 파일 열기에 실패했는지 검사    {                                               // 실패 처리 블록 시작        printf("파일 열기 실패 : %s\n", fileName);  // 어떤 파일이 열리지 않았는지 출력        printf("Error Code : %lu\n", GetLastError()); // 원인 코드 출력 (2 = 파일 없음, 3 = 경로 없음, 5 = 접근 거부, 32 = 다른 프로세스가 사용 중)        return 0;                                   // 실패(0) 반환    }                                               // 실패 처리 블록 끝     /*     * -------------------------------------------------     * 2. SHA-256 알고리즘 공급자 열기     * -------------------------------------------------     */    status = BCryptOpenAlgorithmProvider(&hAlgorithm,             // [출력] 알고리즘 핸들을 받을 변수                                         BCRYPT_SHA256_ALGORITHM, // 사용할 알고리즘: L"SHA256"                                         NULL,                    // 공급자: NULL이면 Windows 기본 공급자                                         0);                      // 플래그: 없음 (HMAC 등을 쓸 때만 지정)     if (status != 0)                                // 0(STATUS_SUCCESS)이 아니면 실패    {                                               // 실패 처리 블록 시작        printf("BCryptOpenAlgorithmProvider 실패\n"); // 오류 메시지 출력        CloseHandle(hFile);                         // 앞 단계에서 연 파일 핸들 반환        return 0;                                   // 실패(0) 반환    }                                               // 실패 처리 블록 끝     /*     * -------------------------------------------------     * 3. SHA-256 해시 객체 크기 확인     * -------------------------------------------------     */    status = BCryptGetProperty(hAlgorithm,              // 조회할 알고리즘 핸들                               BCRYPT_OBJECT_LENGTH,    // 조회 항목: 해시 객체에 필요한 메모리 크기                               (PUCHAR)&hashObjectSize, // [출력] 결과를 저장할 변수 주소 (바이트 포인터로 형변환)                               sizeof(DWORD),           // 출력 버퍼 크기 (DWORD = 4바이트)                               &dataSize,               // [출력] 실제로 기록된 바이트 수                               0);                      // 플래그: 없음     if (status != 0)                                // 속성 조회 실패 여부 검사    {                                               // 실패 처리 블록 시작        printf("BCryptGetProperty 실패\n");         // 오류 메시지 출력        BCryptCloseAlgorithmProvider(hAlgorithm, 0); // 2단계에서 연 알고리즘 공급자 반환        CloseHandle(hFile);                         // 1단계에서 연 파일 핸들 반환        return 0;                                   // 실패(0) 반환    }                                               // 실패 처리 블록 끝     /*     * -------------------------------------------------     * 4. 해시 객체를 저장할 메모리 할당     * -------------------------------------------------     */    hashObject = (unsigned char *)HeapAlloc(GetProcessHeap(), // 현재 프로세스의 기본 힙에서                                            0,                // 플래그 없음 (0으로 초기화하지 않음)                                            hashObjectSize);  // 3단계에서 알아낸 크기만큼 메모리 할당     if (hashObject == NULL)                         // 메모리 할당 실패 여부 검사    {                                               // 실패 처리 블록 시작        printf("메모리 할당 실패\n");               // 오류 메시지 출력        BCryptCloseAlgorithmProvider(hAlgorithm, 0); // 알고리즘 공급자 반환        CloseHandle(hFile);                         // 파일 핸들 반환        return 0;                                   // 실패(0) 반환    }                                               // 실패 처리 블록 끝     /*     * -------------------------------------------------     * 5. SHA-256 Hash 객체 생성     * -------------------------------------------------     */    status = BCryptCreateHash(hAlgorithm,           // 사용할 알고리즘(SHA-256) 핸들                              &hHash,               // [출력] 생성된 해시 객체 핸들                              hashObject,           // 해시 객체가 내부 상태를 저장할 메모리(4단계에서 할당)                              hashObjectSize,       // 위 메모리의 크기                              NULL,                 // 비밀 키: NULL (HMAC이 아닌 일반 해시이므로 키 없음)                              0,                    // 비밀 키 길이: 0                              0);                   // 플래그: 없음     if (status != 0)                                // 해시 객체 생성 실패 여부 검사    {                                               // 실패 처리 블록 시작        printf("BCryptCreateHash 실패\n");          // 오류 메시지 출력        HeapFree(GetProcessHeap(), 0, hashObject);  // 4단계에서 할당한 메모리 해제        BCryptCloseAlgorithmProvider(hAlgorithm, 0); // 알고리즘 공급자 반환        CloseHandle(hFile);                         // 파일 핸들 반환        return 0;                                   // 실패(0) 반환    }                                               // 실패 처리 블록 끝     /*     * -------------------------------------------------     * 6. 파일 내용을 일정 크기로 반복해서 읽는다.     * -------------------------------------------------     * 전체 파일을 한 번에 메모리에 올리지 않고 4096 Byte 단위로 읽는다.     * → 수 GB 크기의 디스크 이미지도 4KB 메모리만으로 해시를 계산할 수 있다.     */    while (1)                                       // 파일 끝(EOF)에 도달할 때까지 무한 반복    {                                               // 반복문 시작        if (!ReadFile(hFile, buffer, BUFFER_SIZE, &readBytes, NULL)) // 최대 4096바이트를 buffer로 읽기, 실패 시 FALSE        {                                           // 읽기 실패 처리 블록 시작            printf("파일 읽기 실패\n");             // 오류 메시지 출력            BCryptDestroyHash(hHash);               // 5단계에서 만든 해시 객체 파괴            HeapFree(GetProcessHeap(), 0, hashObject); // 해시 객체 메모리 해제            BCryptCloseAlgorithmProvider(hAlgorithm, 0); // 알고리즘 공급자 반환            CloseHandle(hFile);                     // 파일 핸들 반환            return 0;                               // 실패(0) 반환        }                                           // 읽기 실패 처리 블록 끝         /* 파일 끝에 도달 */        if (readBytes == 0)                         // ReadFile이 성공했는데 0바이트를 읽었다면 = 파일 끝(EOF)        {                                           // EOF 처리 블록 시작            break; VS Code PowerShell 터미널에서 cl 사용하기

cl.exe는 설치되어 있어도 PATH에 등록되지 않으므로, 일반 PowerShell에서는 개발자 환경을 먼저 불러와야 합니다.

방법 1. 현재 터미널에 개발자 환경 불러오기 (가장 빠름, 터미널을 열 때마다 한 번 실행)

PS> $vs = & "${env:ProgramFiles(x86)}\Microsoft Visual Studio\Installer\vswhere.exe" -latest -products * -requires Microsoft.VisualStudio.Component.VC.Tools.x86.x64 -property installationPath
PS> Import-Module "$vs\Common7\Tools\Microsoft.VisualStudio.DevShell.dll"
PS> Enter-VsDevShell -VsInstallPath $vs -SkipAutomaticLocation -DevCmdArguments "-arch=x64 -host_arch=x64"
PS> cl /W4 /utf-8 file_integrity.c

-SkipAutomaticLocation은 현재 폴더를 유지하고, -arch=x64는 64비트로 컴파일합니다. vswhere.exe를 찾지 못하거나 $vs가 비어 있으면 Visual Studio(Build Tools)나 "C++를 사용한 데스크톱 개발" 워크로드가 설치되지 않은 것입니다.

방법 2. 개발자 프롬프트에서 VS Code 실행하기: 시작 메뉴에서 Developer PowerShell for VS를 열고, 실행 중인 VS Code를 모두 닫은 뒤 실행합니다.

PS> cd D:\University_Project\Joongbu-Forensic\Forensic
PS> code .

확인 where.exe cl 결과로 ...\VC\Tools\MSVC\...\bin\Hostx64\x64\cl.exe가 나오면 성공입니다. PowerShell에서 where는 다른 명령이므로 where.exe로 입력합니다.
